START HERE

The 30-second version

Send a transcript as an array of turns. Get back the redacted transcript, the spans that were found, and a summary. This call is the one most people want:

curl -X POST http://localhost:8000/api/redact \
  -H "Content-Type: application/json" \
  -d '{
    "conversation": [
      {"role": "Agent",    "text": "Who am I speaking with?"},
      {"role": "Customer", "text": "Maya Chen, my card is 4111 1111 1111 1111."}
    ]
  }'
{
  "has_pii": true,
  "categories": ["CreditCard", "Person"],
  "redacted_conversation": [
    {"role": "Agent",    "text": "Who am I speaking with?"},
    {"role": "Customer", "text": "*********, my card is *******************."}
  ],
  "redacted_text": "Agent: Who am I speaking with?\nCustomer: *********, my card is …",
  "entities": [
    {"turn": 2, "category": "Person", "offset": 0, "length": 9, "confidence_score": 1.0}
  ],
  "characters": 71,
  "text_records": 1,
  "duration_ms": 2411.8
}

Every POST takes the same conversation array. role must be "Agent" or "Customer".

EXAMPLES

From your language of choice

Python

import httpx

transcript = [
    {"role": "Agent",    "text": "Thanks for calling, who am I speaking with?"},
    {"role": "Customer", "text": "Maya Chen. My number is 206-555-0148."},
]

# Redact only
redacted = httpx.post(
    "http://localhost:8000/api/redact",
    json={"conversation": transcript},
    timeout=120,
).raise_for_status().json()

print(redacted["categories"])       # ['Person', 'Phone']
print(redacted["redacted_text"])

# Redact, then summarize the redacted transcript, in one call
result = httpx.post(
    "http://localhost:8000/api/pipeline",
    json={"conversation": transcript, "mode": "sequential"},
    timeout=300,
).raise_for_status().json()

print(result["summary"])

JavaScript

const response = await fetch("http://localhost:8000/api/pipeline", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    conversation: [
      { role: "Agent", text: "Who am I speaking with?" },
      { role: "Customer", text: "Maya Chen, card 4111 1111 1111 1111." },
    ],
    mode: "sequential",
  }),
});
if (!response.ok) throw new Error((await response.json()).detail);
const { summary, redacted_text, has_pii } = await response.json();

Calling from a browser on another origin needs CORS. Set CORS_ALLOW_ORIGINS=https://your-app.example.com (comma-separated) on the container; it is off by default, so same-origin and server-side callers work unchanged.

Batch a folder of transcripts

for f in transcripts/*.json; do
  curl -s -X POST http://localhost:8000/api/redact \
    -H "Content-Type: application/json" \
    -d "{\"conversation\": $(cat "$f")}" \
    | jq '{file: "'"$f"'", categories, leaked: .has_pii}'
done

CHOOSING

Which endpoint do I want?

Storing transcripts safely/api/redact
Summarizing already-clean text/api/summarize
Both, in production shape/api/pipeline

mode on /api/pipeline matters. sequential redacts first and summarizes only the redacted transcript, so un-redacted text never reaches the summarizer. parallel starts both at once and re-summarizes only when PII is found — faster on clean transcripts, but it does send un-redacted text to the summarization endpoint on every request. Use sequential unless you have measured that the latency matters and accepted that trade-off.

CONSTRAINTS

Limits and failure modes

  • 1,000 characters per turn. Enforced by Azure, counted in UTF-16 code units. Longer turns must be split before sending.
  • 5,000 characters per transcript. This app's own cap; GET /api/config returns the live values.
  • Both skills are asynchronous jobs. Expect roughly 2–3 seconds per Azure call, so /api/pipeline takes 5 seconds or more. Set generous client timeouts.
  • Errors are JSON. 400 for a transcript that breaks the rules, 422 for a malformed body, 502 when Azure itself fails. The reason is always in detail.
  • Entity spans never include the matched text. Only category, offset, length, and confidence — the value is PII, and you already hold the input it came from.

There is no authentication in front of these endpoints. Azure credentials stay server-side, but anyone who can reach the container can submit transcripts to it — put it behind your own network controls before exposing it beyond localhost.

Evaluating redaction quality?

evaluation/evaluate.py in the repository scores these endpoints against hand-labelled transcripts and reports recall, false positives, and whether any labelled value survived redaction.
